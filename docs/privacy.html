🛡️ Quick Privacy Summary

Social Autopilot is an open-source, self-hosted, local-first, multi-platform social media scheduling and publishing system. We do not operate central user tracking databases, telemetry servers, or data brokerage networks. All configuration files, OAuth tokens, content queues, and generated media assets reside exclusively on the user's host filesystem and communicate directly with user-authorized third-party social-platform APIs and other configured external services.

01 What Social Autopilot Is

Social Autopilot is an open-source, modular, self-hosted, local-first multi-platform social media scheduling and publishing automation system. It enables developers, content creators, and engineering leaders to generate, tailor, and schedule technical posts, infographics, and vertical videos across multiple independently configured social media platform integrations.

02 Self-Hosted & Local-First Architecture

Social Autopilot operates on a self-hosted, local-first architecture where data control remains entirely in the hands of the user:

  • No Remote Control Server: Social Autopilot does not run an intermediary proxy server, centralized database, or telemetry service that collects your credentials or profile activity.
  • Local Configuration Storage: All environment variables, API keys, and access tokens are loaded from local environment files (.env) on the user's machine.
  • Local Task Queue: All scheduled tasks, execution timestamps, custom captions, and publication status records are stored locally in schedule.csv.
  • Local Media Rendering: Media assets (graphic cards, voiceovers, and MP4 vertical videos) are generated and stored locally in the output/ directory.
  • Direct API Communication: Network requests are dispatched directly from the user's local instance to the official endpoints of enabled third-party services.

03 Information Processed by Social Autopilot

Depending on your configuration and workflow, the following categories of data are processed locally and, where enabled, transmitted to external services:

Data Category Local Storage External Transmission & Purpose
API Credentials & Access Tokens Local .env file (gitignored) Transmitted as HTTP Authorization Bearer headers exclusively to the respective external API endpoints (e.g., LinkedIn, Meta, Google Gemini). Never sent to any other third party.
Scheduled Content & Captions Local schedule.csv Platform-adapted captions or user-provided custom text are transmitted to enabled social platform APIs at scheduled execution times.
Generated Media Assets Local output/ directory PNG image cards and MP4 vertical videos are uploaded directly to enabled social platform media endpoints when publishing image or video posts.
Execution & Error Logs Local autopilot.log Stores timestamped execution records, returned post identifiers, and error diagnostics locally for troubleshooting.

04 Multi-Platform Scope & Third-Party Service Interactions

Social Autopilot connects directly to user-authorized external APIs based on the platforms and services enabled in the user's configuration. Each platform integration operates independently and adheres to platform-specific character limits, media rules, and permission scopes.

1. LinkedIn API (LinkedIn REST / Posts & Media Publishing API)

When LinkedIn publishing is enabled, Social Autopilot communicates directly with LinkedIn's official REST API endpoints:

  • Personal Profile Publishing: Publishes member posts and media using the authenticated member's Person URN (urn:li:person:...) and standard member sharing permissions (w_member_social, openid, profile, email).
  • Organization / Company Page Publishing: Publishes organization posts using the target Organization URN (urn:li:organization:...). Requires the application to have approved organization permissions (w_organization_social / Community Management API) and requires the authenticated member to hold an administrative role on the LinkedIn Page. When organization authorization is missing, organization publishing is blocked and fails fast with a clear error.
  • Data Transmitted: Post commentary and caption text, uploaded media binaries (PNG graphic cards / MP4 vertical videos), and the author Uniform Resource Name (URN).
  • Data Received: LinkedIn post identifiers (e.g., urn:li:share:...) and HTTP status codes to record publication state locally.
  • No Scraping or Harvesting: Social Autopilot does not scrape, index, or store LinkedIn user feeds, connections, messages, or member directory data.

2. Meta Graph API (Facebook Page & Instagram Business)

  • Facebook Page Publishing: Uses Meta Graph API (v19.0) with page permissions (pages_manage_posts, pages_read_engagement) to publish text posts, photos, and videos to configured Facebook Pages. Blocked if META_PAGE_ID or META_ACCESS_TOKEN is not configured.
  • Instagram Business Publishing: Integrates with Meta's Graph API Instagram Container workflow for image and Reels publishing. Blocked if INSTAGRAM_ACCOUNT_ID, access tokens, or public media hosting URLs are not configured.
  • Data Transmitted: Page captions, images, and video files sent to Graph API endpoints.

3. Google Gemini API (Optional AI Content Engine)

  • Usage: When keyword or topic-driven content generation is triggered, Social Autopilot calls Google Gemini API models (e.g., gemini-3.6-flash via the official Google GenAI SDK) to generate structured post drafts, takeaways, and video scripts.
  • Data Transmitted: Only the specified post topic, keywords, language setting, and formatting parameters. User profile data and private account credentials are not transmitted to Gemini.
  • Exact Custom Caption Bypass: When a user supplies an exact custom caption (via --caption or custom_caption), the Google Gemini API call is completely bypassed.

4. Microsoft Edge TTS (Voiceover Synthesis)

  • Usage: Synthesizes neural voiceover audio files for 9:16 vertical videos using Microsoft Edge Neural TTS voices (e.g., en-US-ChristopherNeural or bn-BD-PradeepNeural).
  • Data Transmitted: The text narration string is transmitted over HTTPS to Microsoft's Edge TTS service to synthesize the requested MP3 audio stream.

5. Future & Additional Platform Integrations

Social Autopilot's modular adapter architecture is designed to support additional social networks (such as X/Twitter, Threads, YouTube, and others) as independent, toggleable integrations. Any newly added platform will follow the same local-first principles: independent credentials, explicit user opt-in, strict character limit validation, and zero centralized data collection.

05 Cookies, Analytics, and Telemetry

Zero Web Tracking: Social Autopilot contains no web cookies, tracking pixels, telemetry beacons, or third-party analytics SDKs. The application does not collect IP addresses, hardware identifiers, or runtime usage statistics.

06 Data Retention and User Deletion Rights

Because all data is stored locally on the user's host system:

  • Full Data Control: You can delete all local records at any time by deleting schedule.csv, clearing the output/ directory, or removing your .env files.
  • Revoking Permissions: You can revoke Social Autopilot's access to your social accounts at any time via your LinkedIn Developer App settings or Meta App Permissions. Revocation immediately terminates the application's ability to publish to those accounts.

07 Security Measures

Social Autopilot enforces strict local security best practices:

  • Git Exclusion: The repository's .gitignore strictly excludes all .env* credential files, virtual environments, runtime logs, and media output from being committed to version control.
  • Zero Hardcoded Secrets: No OAuth tokens, client secrets, or private keys are hardcoded in source files or public documentation.
  • Atomic Storage Operations: Schedule state updates are written atomically using temporary files and safe replacements to prevent data corruption.

08 Children's Privacy

Social Autopilot is intended for software developers, content creators, and business professionals. It is not designed or intended for use by individuals under the age of 13.
